# MySQL 一张表最多可以有多少列？

日期：2026-07-11  
难度：简单  
标签：#面试 #MySQL #InnoDB #表设计 #VIP

## 一句话答案

MySQL Server 层理论硬上限是 4096 列，但 MySQL 8.4 的 InnoDB 表最多 1017 列；实际通常更早受 65,535 字节行大小、页内记录、索引和字段类型限制。

## 面试口语版

这题要区分 Server 和存储引擎。MySQL 定义的理论列数上限是 4096，但默认 InnoDB 的限制是 1017 列，而且虚拟生成列也计入；函数索引通过隐藏生成列实现，同样会消耗列名额。即使不到 1017，也可能因为所有非页外字段的最大定义长度超过 MySQL 65,535 字节行大小而建表失败。工程上几百上千列本身就是建模、缓存和维护风险，不应把理论上限当设计目标。

## 原理拆解

| 限制层 | 典型上限/影响 |
| --- | --- |
| MySQL Server | 最多 4096 列 |
| InnoDB 8.4 | 最多 1017 列 |
| MySQL 行大小 | 非 BLOB/TEXT 等合计最大约 65,535 字节 |
| InnoDB 页内记录 | 默认 16KB 页下还受本地行大小限制 |

## 关键细节

- 具体上限依版本、存储引擎、行格式和页大小而变化，应查目标版本文档并实际建表验证。
- BLOB/TEXT 可页外存储，但仍有行内指针和整个记录的其他限制。
- 超宽表可能导致 `SELECT *`、网络、ORM 映射、DDL 和 Buffer Pool 利用率恶化。

## 面试官追问

1. 为什么还没到 1017 列就可能建表失败？
2. TEXT 为什么能缓解行大小限制？
3. 函数索引为什么影响列数？

## 高分补充

如果业务出现数百个动态属性，应评估子表、JSON、EAV 或列式/分析存储，而不是继续扩宽核心 OLTP 表。

## 学习清单

- 记住 4096、1017、65,535 三个不同层次的限制。
