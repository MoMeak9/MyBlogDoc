## 🏢 一、行业分类术语（基础必会）

### 1. **to B / to C / to G**

**📖 定义**：
- **to B**（To Business）：面向企业客户
- **to C**（To Customer）：面向个人消费者
- **to G**（To Government）：面向政府机构

**💡 实际案例**：
- **to B**：钉钉（企业协作）、Salesforce（CRM系统）、企业微信
- **to C**：微信、抖音、美团、淘宝
- **to G**：政务服务APP、电子政务平台

**🎯 使用场景**：
```
老板："我们这个产品是to B的，要考虑企业采购流程"
理解：目标用户是企业，不是个人，要关注企业决策链
```

**⚖️ 关键区别**：
| 维度 | to B | to C |
|------|------|------|
| 决策链 | 复杂（多人决策） | 简单（个人决策） |
| 销售周期 | 长（几周到几月） | 短（即时购买） |
| 客单价 | 高（几千到几百万） | 低（几元到几千） |
| 关注点 | 效率、ROI、稳定性 | 体验、便捷、价格 |

---

### 2. **IAP（In-App Purchase）**

**📖 定义**：苹果应用内支付，购买虚拟商品时苹果会抽成30%

**💡 实际案例**：
- 游戏内购买道具、皮肤
- 视频会员续费
- 知识付费课程

**⚠️ 注意事项**：
- 虚拟商品必须走IAP（苹果强制要求）
- 实体商品可以不走IAP（如电商、外卖）
- 抽成30%，影响定价策略

**🎯 使用场景**：
```
技术："这个充值功能要走IAP吗?"
产品："我们卖的是虚拟币，必须走IAP，定价要考虑30%抽成"
```

## 📄 二、产品文档类型

### 3. **BRD / MRD / PRD**

**📖 定义**：
- **BRD**（Business Requirement Document）：商业需求文档
- **MRD**（Market Requirements Document）：市场需求文档
- **PRD**（Product Requirement Document）：产品需求文档

**🔄 文档关系**：
```
BRD（为什么做）→ MRD（市场机会）→ PRD（怎么做）
```

**📝 各文档重点**：

| 文档 | 核心内容 | 读者对象 | 什么时候写 |
|------|---------|---------|-----------|
| BRD | 商业价值、投资回报、战略目标 | 老板、投资人 | 立项前 |
| MRD | 市场分析、用户画像、竞品分析 | 运营、市场 | 规划阶段 |
| PRD | 功能需求、交互逻辑、优先级 | 研发、测试、设计 | 开发前 |

**💡 实际案例**：
```
BRD：我们要做一个外卖APP，预计3年收回成本
MRD：外卖市场每年增长20%,25-35岁白领是主力用户
PRD：首页需要定位功能，搜索框，商家列表...
```

**🎯 新人重点**：
- 大公司：三个文档分开写
- 小公司/创业公司：通常只写PRD
- 日常工作：PRD写得最多

## 📊 三、营销推广术语

### 4. **SEM / SEO**

**📖 定义**：
- **SEM**（Search Engine Marketing）：搜索引擎营销（付费推广）
- **SEO**（Search Engine Optimize）：搜索引擎优化（免费优化）

**⚖️ 区别对比**：
| 维度 | SEM | SEO |
|------|-----|-----|
| 成本 | 付费（按点击/展示） | 免费（但需人力） |
| 见效速度 | 立即见效 | 3-6个月见效 |
| 持续性 | 停止付费立即消失 | 长期有效 |
| 典型方式 | 百度竞价、Google Ads | 内容优化、关键词优化 |

**💡 实际案例**：
- **SEM**：百度搜索"产品经理培训"，前几条带"广告"字样的就是SEM
- **SEO**：通过优化文章内容和关键词，让你的网站自然排名靠前

**🎯 使用场景**：
```
运营："我们这个月预算不多，先做SEO吧"
产品："好的，我们优化一下文案和关键词密度"
```

---

### 5. **拉新 / 留存 / 促活**

**📖 定义**：
- **拉新**：获取新用户
- **留存**：让用户持续使用
- **促活**：让用户更活跃

**🔄 用户生命周期**：
```
拉新（获客）→ 激活（首次使用）→ 留存（持续使用）→ 促活（活跃度提升）→ 变现
```

**💡 实际案例**：
- **拉新**：
  - 方法：广告投放、裂变活动、地推
  - 案例：拼多多砍一刀、瑞幸咖啡首单免费

- **留存**：
  - 方法：新手引导、签到奖励、push推送
  - 案例：keep签到打卡、微信读书组队读书

- **促活**：
  - 方法：活动运营、内容推荐、社交互动
  - 案例：抖音推荐算法、小红书话题挑战

**📊 衡量指标**：
- 拉新：新增用户数、获客成本（CAC）
- 留存：次日留存率、7日留存率、30日留存率
- 促活：日活（DAU）、月活（MAU）、人均使用时长

**🎯 使用场景**：
```
老板："这个月重点是拉新还是留存？"
产品："现在用户基数小，先拉新；达到10万用户后再重点做留存"
```

## 💡 快速记忆技巧

### 📌 场景联想法

**开会场景模拟**：
```
老板："我们要做一个to B的SaaS产品"
→ 理解：面向企业的软件服务产品

运营："这个月SEM预算不够，重点做SEO拉新"
→ 理解：付费推广钱不够，做免费优化获取新用户

技术："苹果商店的充值要走IAP"
→ 理解：虚拟商品购买要用苹果支付，会被抽成30%

测试："PRD里没写清楚这个交互逻辑"
→ 理解：产品需求文档没说明白这个功能怎么做
```

### 🎯 对比记忆法

**to B vs to C**：
- B = Business（企业有钱，决策慢）
- C = Customer（个人没钱，决策快）

**SEM vs SEO**：
- SEM = Money（花钱买排名）
- SEO = Organic（自然优化）

**BRD vs MRD vs PRD**：
- BRD = 老板关心（赚不赚钱）
- MRD = 运营关心（市场多大）
- PRD = 研发关心（怎么实现）

## 📊 术语使用场景

| 场景 | 常用术语 | 示例 |
|------|---------|------|
| 需求评审 | PRD、to B/C、IAP | "这个PRD还没写完" |
| 运营会议 | SEM、SEO、拉新、留存 | "本月拉新1万，次留65%" |
| 战略会议 | BRD、MRD、to B/C/G | "我们的BRD下周给老板" |
| 技术对接 | IAP、API、SDK | "充值走IAP还是支付宝?" |

## 📌 总结

**记住这3组核心：**

**1. 业务方向**：
- to B：企业客户（钉钉、Salesforce）
- to C：个人用户（微信、美团）
- to G：政府项目（政务APP）

**2. 文档类型**：
- BRD：给老板看（为什么做）
- MRD：给运营看（市场机会）
- PRD：给研发看（怎么做）

**3. 运营术语**：
- SEM：花钱推广（见效快）
- SEO：免费优化（见效慢）
- 拉新/留存/促活：用户运营三板斧

**新人学习建议**：
- ✅ 遇到不懂的术语立即查询
- ✅ 建立自己的术语手册
- ✅ 多参加会议，在实战中学习
- ❌ 不懂装懂，会害死项目
